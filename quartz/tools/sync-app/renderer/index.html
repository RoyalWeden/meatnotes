Your .git folder is inside iCloud

iCloud's sync daemon occasionally duplicates files while git is writing to them, creating quartz 2/.git 2 artifacts and corrupting pushes. Moving .git to ~/.local/share/meatnotes-git (and leaving a gitdir: pointer) eliminates this race. Your notes stay in iCloud as before; only git's internals move.

Maintenance


          

            

              
Remove iCloud duplicate files

              

                What: Scans for files like quartz 2.md or .git 2/ — artifacts created when iCloud's sync daemon duplicates files while git is writing them. Shows them for review, then git rms and commits.

                When to run: You see " 2"-suffixed files in the sidebar, or a recent sync failed with "push referenced unknown Git LFS objects".

                Reversible: Yes — git revert the cleanup commit.
              

            

            
          


          

            

              
Move .git out of iCloud

              

                What: .git holds git's internal database. Keeping it in iCloud means the iCloud daemon can corrupt it mid-write. This moves .git to ~/.local/share/meatnotes-git and leaves a one-line gitdir: pointer file in the repo, so git still works and your notes stay where they are.

                When to run: Once per machine. Strongly recommended.

                Reversible: Yes — use "Move back".

                Checking current location…
              

            

            
          


          

            

              
Auto-clean duplicates before every sync

              

                What: Before each sync, scan for " N" duplicates and silently git rm any whose un-suffixed twin exists. Logs what was removed to Activity.

                When to run: Leave on. Catches the residual risk that an iPhone edit lands in iCloud mid-sync.

                Reversible: Yes — toggle off any time; each auto-clean is a normal revertable commit.
              

            

            
          


          

            

              
Show the iCloud warning banner

              
When off, hides the Overview banner about .git still being inside iCloud. Turn on to see it again.

            

            
          


          

            

              
Move website-only notes to Website/

              

                What: Scans content/ for notes whose frontmatter has publish: true and moves them into content/Website/. Any wiki-links that included a folder path get rewritten to point at the new location. Bare [[Note Name]] links are left alone — Quartz resolves them by filename.

                When to run: After tagging notes you want on the public site with publish: true. Organizational only — does not change what Quartz publishes.

                Reversible: Yes — git revert the resulting commit.
                

              

            

            

              
              
            

          

        


        

          
Does this cover every iCloud sync issue?

          
Mostly yes, with one residual risk.

          
    
            
  • Fixed — the biggest race: .git writes conflicting with iCloud sync. Once .git is moved, git can never trigger iCloud duplicates.
    • 
            
  • Fixed — stale " 2" files already in the repo (Clean up…) and prevention going forward (Auto-clean above).
    • 
            
  • Remaining — an edit from your iPhone that lands in iCloud the same second as a desktop commit could still, in theory, create a " 2" file under content/. Auto-clean catches these on the next sync. There's no way to eliminate this entirely without moving content/ out of iCloud too — which would defeat the purpose of the setup.
